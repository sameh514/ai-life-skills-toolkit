# Reusable learnings

## AI works best as scaffolding, not substitution

The useful role is often external structure: hold the task state, show one next
action, preserve a resume point, and verify what actually happened. The person
still learns, decides, approves, and completes the meaningful work.

## Reduce activation energy

Large tasks become easier to start when the system exposes the smallest useful
action instead of presenting an entire project. After an interruption, resume
from the last verified state rather than restarting everything.

## Minimize interruptions

Use known context and safe, reversible defaults before asking for more input.
Bundle questions that do not block progress, keep useful work moving while an
answer is pending, and never ask again for information already provided. Stop
only when a missing choice changes the result, exposes private information,
spends money, grants authority, or makes something hard to undo.

## Distinguish completion states

Requested, drafted, submitted, processing, confirmed, delivered, accepted, and
resolved are different states. A good workflow records the exact state and the
evidence required to advance it. This matters in customer support, renewals,
publishing, purchases, coursework, and file delivery.

## Build learning artifacts from verified sources

Use a shared Course Source Pack when several artifacts consume the same
material. A Course Source Pack is simply one folder or file that lists the
approved course sources, key terms and pronunciations, and which material is
graded. Record those decisions once so workbooks and podcasts do not quietly
contradict one another.

## Match the medium to the target

- Audio is useful for preview, explanation, and oral retrieval.
- Paper is useful for diagrams, calculations, and handwriting.
- Hands-on tools are required for hands-on skills: a code editor for coding and
  paper or a drawing surface for handwriting.
- Presentations are useful when an audience needs a clear visual story.

Engagement alone is not evidence that a medium teaches the required skill.

## Fade help toward independence

A strong progression is:

1. diagnose without help;
2. show one concrete worked example when needed;
3. ask for self-explanation;
4. provide faded or ordered practice;
5. require a materially different independent attempt;
6. give feedback after a committed answer;
7. check again later without support.

Recognition, listening, and immediate familiarity do not prove durable mastery.

## Protect answer boundaries

For workbooks and coding practice, keep learner pages before a prominent STOP
and answer keys afterward. Scrambled same-page word banks can reduce search
friction without placing answers in order. Active graded assessments require
analogous practice and reasoning support, not copied questions or submitted
answers.

## Use light access supports

When attention, working memory, or task-state loss is the barrier, start with
one or two functional changes: reduce clutter, write one next action, externalize
changing state in a table, or leave a clear resume point. Do not assume a
diagnosis requires a special dashboard, timer system, or lower mastery standard.

## Verify artifacts, not intentions

Render every important PDF page, decode the whole audio, run executable tests,
inspect presentation slides, and compare hashes after a requested copy.
“Generated” is not the same as “verified.”

## Keep consequential actions reviewable

Before an irreversible publication, purchase, deletion, submission, or account
change, show the exact target and final state. Never treat notification as
approval. After acting, verify the result instead of inferring success from a
button click or spinner.

## Minimize personal data

Store non-sensitive preferences separately from sensitive profile fields.
Retrieve only the field needed for the current task. Never publish raw memory,
conversation history, addresses, credentials, medical records, school accounts,
private course sources, or full financial identifiers.
